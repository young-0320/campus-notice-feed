# campus-notice-feed

대학 공지 게시판을 주기적으로 크롤링해 신규 글을 GitHub Issue로 알려주는
서버리스 봇. 이슈 생성 시 GitHub이 알림 메일을 보내고, 설정하면 Discord와
지정한 이메일 주소로도 보낸다. GitHub Actions에서만 돌기 때문에 서버·비용이
없다.

> 현재는 경희대 국제캠퍼스의 전자공학과·공과대학·생명과학대학 사이트 19곳을
> 감시한다. 경희대 학과 사이트 대부분이 같은 게시판 시스템을 써서 설정
> 파일에 사이트를 추가하는 것만으로 확장된다. 타 학교로의 일반화는 예정.

## 감시 대상

감시할 사이트와 게시판은 **`sites.toml`** 에 있다 (파이썬 코드를 건드릴 필요 없음).

| 단과대 | 사이트 |
|---|---|
| 전자정보대학 | 전자공학 |
| 공과대학 | 공과대학, 기계공학, 산업경영공학, 원자력공학, 화학공학, 신소재공학, 사회기반시스템공학, 건축공학, 환경공학, 건축학 |
| 생명과학대학 | 생명과학대학, 유전생명공학, 식품생명공학, 한방생명공학, 식물환경신소재공학, 원예생명공학, 스마트팜과학, 융합바이오신소재공학 |

각 사이트에서 공지 성격의 게시판만 골랐다(취업정보·교육과정·자료실 등은
제외). 넣고 빼는 법은 아래 "사이트 추가" 참고.

## 구성

```
check_notices.py                    # 크롤링·신규 판별·이슈 본문 생성·알림 전송
sites.toml                          # 감시 대상 사이트·게시판·필터 설정
keywords.txt                        # 관심 키워드 목록 (⭐ 하이라이트 / 필터)
sitecheck.py                        # 사이트 형식 검사기 + 등록 사이트 검증기
.github/workflows/khu-notice.yml    # 3일마다 실행하는 GitHub Actions
seen.json                           # 본 글 ID 상태 (봇이 자동 커밋, 최초엔 없음)
log.md                              # 기능 목록·설계 변경 기록·확장 방법
```

## 설치

1. 이 리포지토리를 그대로 사용하거나 fork 한다.
2. **Settings → Actions → General → Workflow permissions**
   → `Read and write permissions` 체크 (seen.json 커밋·이슈 생성에 필요)
3. **Actions 탭 → "KHU EE 공지 감시" → Run workflow**로 수동 1회 실행

첫 실행은 기존 글을 전부 baseline으로 저장하고 알림을 보내지 않는다.
`seen.json`이 커밋되면 정상. 이후 실행부터 신규 글만 잡는다.
(단, 첫 실행에서 파서가 깨진 게 감지되면 baseline 대신 점검 이슈를 띄운다.)

## 알림 메일 받기

리포지토리 우측 상단 **Watch → All Activity** 로 설정하면
이슈 생성 시 GitHub 계정 메일로 알림이 온다.

## 이메일 알림 받기 (선택)

GitHub 계정이 없는 사람에게도 보내려면 Secret 3개를 설정한다. 하나라도
없으면 자동으로 생략된다. 발송은 Gmail SMTP를 쓴다.

1. 발신용 Gmail 계정에서 2단계 인증을 켜고 **앱 비밀번호**를 만든다
   (Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호).
2. GitHub repo → **Settings → Secrets and variables → Actions →
   New repository secret** 으로 아래 3개를 등록한다.

| Secret | 값 |
|---|---|
| `SMTP_USER` | 발신 Gmail 주소 |
| `SMTP_PASSWORD` | 위에서 만든 앱 비밀번호(16자, 공백 없이) |
| `MAIL_TO` | 받는 사람 주소. 여러 명이면 쉼표로 구분 |

받는 사람을 추가·삭제하려면 `MAIL_TO` 값을 고친다. 수신자끼리는 서로의
주소가 보이지 않는다(숨은참조로 발송).

> ⚠️ 주소와 앱 비밀번호는 **Secret에만** 넣는다. 퍼블릭 레포의 파일에
> 적으면 누구나 볼 수 있다. Gmail은 하루 발송량 제한이 있어 수십 명
> 규모까지만 적합하다.

## Discord 알림 받기 (선택)

`DISCORD_WEBHOOK` Secret을 설정하면 신규 공지/수집 실패 알림이
Discord 채널로도 전송된다. 미설정 시 자동으로 생략된다.

1. Discord 채널 → 톱니바퀴(채널 편집) → **Integrations → Webhooks →
   New Webhook** → **Copy Webhook URL**
2. GitHub repo → **Settings → Secrets and variables → Actions →
   New repository secret** → 이름 `DISCORD_WEBHOOK`, 값에 복사한 URL

> ⚠️ Webhook URL은 **Secret에만** 넣는다. URL을 아는 사람은 누구나 그
> 채널에 메시지를 보낼 수 있으므로 채팅·커밋·이슈에 절대 붙여넣지 말 것
> (퍼블릭 레포에서 특히 주의). 유출 시 Discord에서 webhook을 삭제하고
> 새로 만들면 된다.

## 로컬 실행

```bash
pip install requests beautifulsoup4
python check_notices.py
```

파이썬 3.11 이상이 필요하다(`sites.toml` 을 표준 라이브러리 `tomllib` 로 읽는다).

`GITHUB_OUTPUT` 환경변수가 없으면(로컬) 이슈 생성 없이 결과만 출력한다.

## 키워드 하이라이트

제목에 관심 키워드가 있으면 이슈에서 ⭐ 섹션으로 따로 묶인다.
키워드는 **`keywords.txt`** 파일에서 수정한다 (파이썬 코드를 건드릴 필요 없음).

- 한 줄에 키워드 하나
- `#`로 시작하는 줄과 빈 줄은 무시 (카테고리 주석용)
- 대소문자 구분 안 함 (`FAB` == `fab`)
- 한글 키워드는 부분일치 (`공모` → "공모전"도 매칭)
- 영문·숫자 키워드는 단어 단위 (`AI` → "AI 특강", "AI융합"은 매칭,
  "Fair"·"email"은 매칭 안 함)
- 파일을 지우거나 비우면 `check_notices.py`의 `DEFAULT_KEYWORDS`로 폴백

GitHub 웹에서 `keywords.txt`를 열어 바로 편집·커밋해도 된다.

## 키워드 필터 (사이트별)

공지가 너무 많은 사이트는 키워드가 있는 글만 받도록 바꿀 수 있다.
`sites.toml` 에서 그 사이트의 `filter` 값을 고친다.

| 값 | 동작 |
|---|---|
| `filter = "all"` | 신규 글을 전부 알림 (기본값) |
| `filter = "keywords"` | 제목에 `keywords.txt` 의 키워드가 있는 글만 알림 |

필터는 이슈·Discord·이메일 모두에 적용된다. 걸러진 글은 다시 알리지
않으며, 몇 건이 걸러졌는지는 Actions 실행 화면의 요약 표("필터 제외")에
나온다. 한글 키워드는 부분일치라 `교육` 같은 넓은 단어는
"교육혁신사업단"에도 걸리니, 필터를 켤 때는 키워드를 좁게 잡는 게 좋다.

## 사이트 추가

경희대 학과 사이트는 대부분 같은 게시판 시스템이지만 전부는 아니므로,
넣기 전에 검사기로 확인한다.

```bash
pip install requests beautifulsoup4

# 1. 형식 검사 — 게시판을 찾아 읽어 보고 sites.toml 초안을 출력한다
python sitecheck.py inspect https://me.khu.ac.kr

# 2. 초안에서 공지 성격의 게시판만 남겨 sites.toml 에 붙여 넣는다

# 3. 검증 — 등록된 게시판이 실제로 읽히는지 확인한다(알림은 보내지 않음)
python sitecheck.py validate            # 전체
python sitecheck.py validate 기계공학    # 한 사이트만
```

검사기 판정:

| 판정 | 뜻 |
|---|---|
| `OK` | 지금 파서로 읽힌다. 그대로 등록 가능 |
| `WARN` | 읽히지만 날짜가 없는 등 공지 게시판이 아닐 수 있다 |
| `FAIL` | 못 읽는다. 교수소개·갤러리·Q&A 게시판은 원래 이렇게 나온다 |
| "게시판 링크를 찾지 못했다" | 다른 시스템을 쓰는 사이트이거나, 게시판 없이 학과 사이트로 연결만 하는 단과대 포털 |

새로 넣은 게시판은 첫 실행에서 기존 글을 baseline으로만 저장하고
알리지 않는다. 그다음 실행부터 신규 글이 온다.

## 게시판 레이아웃 (두 종류)

게시판마다 목록 마크업이 다르다. 파서는 둘 다 자동 처리한다.

- **표형** (`BMSR00040`: 학사/장학·취업정보·기타공지) — `<table><tbody><tr>`
- **썸네일 카드형** (`BMSR00044`: 소식·행사) — `<ul class="bbs-thumb"><li>`

`소식`·`행사` 외에 학과 사이트의 공지 게시판은 거의 전부 표형이다.

## 파서 건강검사 (마크업 변경 감지)

학교가 게시판 마크업을 바꾸면 파서가 아무것도 못 잡으면서도 에러 없이
"신규 0건"처럼 보이는 **조용한 실패**가 일어날 수 있다. 이를 잡기 위해
사이트가 표시하는 **"전체 N 건"**(`.bbs-total`)을 기준으로 삼는다:

- 전체 글이 있는데(N>0) 실제 추출 수가 기대치(`min(N, 페이지 크기)`)의
  `PARSE_RATE_MIN`(0.7) 미만이면 → **"파서 점검 필요" 이슈**를 띄운다.
- 전체 0건(빈 게시판)은 정상으로 보고 경고하지 않는다.

이 이슈가 오면 `check_notices.py`의 셀렉터(`tbody tr` / `ul.bbs-thumb > li`)나
`ID_RE`(`view('id')` 패턴), `.bbs-total` 파싱을 실제 페이지에 맞게 손봐야 한다.
어느 게시판이 어떻게 깨졌는지는 `python sitecheck.py validate` 로 바로 볼 수 있다.

## 같은 공지가 여러 학과에 올라올 때

본부·단과대 공지는 여러 학과 게시판에 그대로 다시 올라온다. 한 번의
실행에서 제목이 같은 글은 `sites.toml` 에서 위쪽에 있는 사이트의 것 하나만
남기고 "외 N곳"으로 표시한다. 제목이 조금이라도 다르면 따로 나온다.

  (2026-11-22, `sitecheck.py validate`).
  단 학교가 마크업을 바꾸면 깨질 수 있으니 위 건강검사가 이를 감지한다.
- 게시글 ID는 `view('546618')` 패턴에서 정규식으로 추출한다.
  목록 번호는 상단 고정 공지 때문에 불안정하므로 쓰지 않는다.
- 이슈 제목/본문은 게시글 텍스트(외부 입력)를 파일로 넘겨 생성한다.
  스크립트 인젝션 방지를 위해 `${{ }}` 인라인을 쓰지 않으니 워크플로 수정 시 주의.
